# WebClip 記事保存

Web ページの記事を丸ごと取り込み、**元ページのリンクと一緒に**保存・管理する単一 HTML の Web アプリです。
`WebClip.html` をブラウザで開くだけで動作します。外部ライブラリは使いません。
https で公開すると、スマホ・タブレットにアプリとしてインストールできます（PWA、v1.1）。アプリ自身は外部と通信しません（保存した記事の画像は、表示するときに元サイトから読み込みます）。

## 取り込みの方法

### 1. ブックマークレット（おすすめ）

- アプリの「ブックマークレット」からブックマークレットを登録します。
- 保存したいページで実行すると、ページ下部にパネルが出ます。
  - **本文**：広告・メニュー・サイドバー・共有ボタン・関連記事・コメント欄などを除いて、記事の本文を自動で抜き出します。抜き出した範囲は、ページ上に青い枠で表示されます。
  - **全体**：ページ全体を取り込みます（script・非表示要素などは除きます）。
  - **選択**：ページで文字を選択してから実行したときに出ます。選択した部分だけを取り込みます。
- 「コピー」を押してから WebClip の「＋ 取込」に貼り付け、内容を確認して「保存」します。
- アプリを https（GitHub Pages など）で開いて登録した場合は、「アプリへ送る」も使えます。新しいタブで WebClip が開き、確認画面に直接届きます。
- 自分がログインして見ているページ（会員限定記事など）も、画面に表示されている内容であれば取り込めます。
- 次の情報も一緒に取り込みます：URL、canonical URL、サイト名、著者、公開日、概要、OGP 画像。
- 遅延読み込みの画像（data-src など）は実際の画像 URL に、相対リンク・相対画像は絶対 URL に直します。
- **画像も保存**（v1.2、既定でオン）：パネルを開くと、記事の画像の取得を始めます。取得できた画像は本文に埋め込んで端末に保存するので、元ページや元の画像が消えても表示できます。
  - パネルに「3/5枚を保存」のように、取得の状況を表示します。取得が終わるまで「コピー」は押せません。「アプリへ送る」は、取得が終わってから送ります。
  - 記事と同じサイトにある画像は、基本的に取得できます。別のサイト（画像配信サーバーなど）にある画像は、そのサイトが他サイトからの読み込みを許可（CORS）している場合だけ取得できます。ページのセキュリティ設定（CSP）で禁止されている場合も取得できません。
  - 取得できなかった画像は、これまでどおり元の URL を参照します。
  - 300KB 以下の PNG・JPEG・GIF・WebP はそのまま保存します。それ以外は、長辺 1600px 以内の JPEG（品質 85%）に変換して保存します（透過部分は白になり、GIF アニメは止まります）。
  - 一度に取得する画像は 80 枚までです。
  - チェックを外すと、画像は URL 参照のみになります。

### 2. 貼り付け

- 記事ページを全選択（または一部を選択）してコピーし、「＋ 取込」に貼り付けます。書式（見出し・リスト・表・リンク・画像）を残して取り込みます。
- この方法では URL が自動で入らないので、URL 欄に入力するか、続けて URL を貼り付けてください（URL を貼り付けると URL 欄に入ります）。
- 一覧画面で Ctrl+V を押しても取り込めます。
- 「クリップボードから読込」ボタンでも取り込めます。ブラウザが許可を求めることがあります。

### 3. リンクのみ

- URL だけを貼り付けると、本文なしの「リンクのみ」で保存します。

## リンクの管理

- 記事ごとに元ページの URL を保存します。閲覧画面には次のボタンがあります：「元ページを開く」「リンクをコピー」「Markdown リンクをコピー」。
- 一覧の ↗ ボタンからも元ページを開けます。
- 一覧はサイト（ドメイン）で絞り込めます。
- 同じ URL の記事を保存しようとすると警告します。判定では次を無視します：`#` 以降、`utm_*` などの計測用パラメータ、http と https の違い、末尾の `/`。canonical URL での一致も重複とみなします。
  - 保存時は「上書き」「別の記事として保存」「キャンセル」から選べます。
  - 上書きの場合は、保存日・タグ・メモを引き継ぎます（タグは新旧を合わせます）。
- 「バックアップ」→「リンク一覧」で、サイトごとにまとめた Markdown のリンク一覧を書き出せます（保存・コピー）。一覧で絞り込んでいる場合は、表示中の記事だけを書き出します。

## 一覧・閲覧

- 検索の対象は、タイトル・本文・URL・サイト名・メモ・タグです。スペースで区切ると AND 検索になり、`#タグ` と書くとタグの完全一致で絞り込みます。
- 絞り込み：サイト、タグ（v1.2）。
- 並べ替え：保存日（新しい順・古い順）、タイトル順、サイト順、手動（v1.2）。選んだ並べ替えは次回も使います。
- タグ・メモの付与、タイトル・URL・サイト名の編集ができます。

### 手動の並べ替えと仕切り（v1.2）

- 並べ替えで「手動（並べ替え・仕切り）」を選ぶと、各行の左につまみ（⋮⋮）が出ます。つまみをドラッグ（スマホは長押しせずにそのまま指で）して並べ替えます。リストの上端・下端に近づけると自動でスクロールします。
- 「＋ 仕切り」で、一覧に見出しの帯（仕切り）を追加できます。文字は空欄でもかまいません（線だけになります）。いちばん上に追加されるので、ドラッグで好きな位置へ動かしてください。
- 仕切りをタップすると、文字の編集・削除ができます。仕切りを削除しても記事は消えません。
- 新しく保存した記事は、いちばん上に入ります。
- 検索・サイト・タグで絞り込んでいる間は、並べ替えと仕切りの表示を止めます（記事は手動の順で並びます）。

### タグ（v1.2）

- タグ欄では、付けたタグを「#タグ ×」のチップで表示します。× で外せます。
- 欄の下に、過去に使ったタグを使用回数の多い順にボタンで表示します。タップすると追加できます。
- 文字を入力すると候補を絞り込みます。まだ無いタグは「＋ 新しいタグ」として追加できます。Enter でも追加できます（日本語の変換中の Enter は無視します）。
- 閲覧画面の「タグ編集」（タグが無い記事は「＋ タグ」）から、すぐにタグを編集できます。
- 一覧の「タグ管理」では、タグの名前の変更と削除を、全記事にまとめて反映できます。既にあるタグと同じ名前に変えると、2つのタグを1つにまとめます。
- 閲覧画面の文字サイズを変えられます（12〜24px）。
- 狭い画面（スマホ・縦向きの iPad mini など）では、一覧と閲覧を切り替えて表示します。ブラウザの「戻る」で一覧に戻れます。

## 書き出し

- 記事ごとに次の形式で書き出せます。
  - **Markdown**：Obsidian 向けに front matter（title・source・site・author・published・clipped・tags）を付けます。コピーか `.md` ファイルの保存を選べます。
  - **HTML**：1 ファイルで開ける HTML です。
- 全件のバックアップ（JSON）の書き出しと読み込みができます。仕切り・並び順・保存した画像も含みます。読み込みは追加・統合で、同じ ID の記事は更新日時が新しいほうを残します。

## 保存データ

- ブラウザの IndexedDB（データベース名 `webclip`）に保存します。
  - `clips`：一覧用の情報（タイトル・URL・タグ・メモ・検索用テキストなど）
  - `bodies`：本文 HTML
- 本文はすべて許可リスト方式でサニタイズしてから保存・表示します。script・イベント属性・style・iframe・`javascript:` リンクなどは除きます。
- 端末間の同期はありません。JSON バックアップで移してください。
- データはブラウザ・端末ごとに別々です。同じ端末でも、ファイルとして開いた場合と https で開いた場合は別の保存領域になります。
- iPad・iPhone の Safari では、ホーム画面に追加していないサイトのデータが、しばらく使わないと削除されることがあります。定期的に JSON バックアップを書き出してください（「バックアップ」画面に最終書き出し日時を表示します）。

### バックアップ JSON の形式（format 1）

```json
{
  "app": "WebClip", "format": 1, "version": "1.0.0", "exportedAt": "2026-11-27T…",
  "clips": [
    { "id": "c…", "kind": "article", "url": "https://…", "canonical": "", "title": "…", "site": "…",
      "author": "", "published": "", "excerpt": "", "image": "", "text": "…", "chars": 1234, "images": 2,
      "tags": ["…"], "memo": "", "createdAt": "…", "updatedAt": "…", "order": 0, "html": "<p>…</p>" }
  ]
}
```

`kind` は `article`（本文）、`page`（ページ全体）、`selection`（選択範囲）、`paste`（貼り付け）、`link`（リンクのみ）、`divider`（仕切り、v1.2）のいずれかです。

- `order`（v1.2）：手動の並び順です。小さいほど上に並びます。`order` が無いデータ（v1.1 以前のデータや古いバックアップ）を読み込んだときは、保存日の新しい順で自動的に番号を付けます。
- 保存した画像は、`html` の中に `data:image/…;base64,…` として入っています。画像を保存するとバックアップのサイズが大きくなります。
- v1.1 以前のアプリで v1.2 のバックアップを読み込むと、仕切りは空の「貼り付け」記事として読み込まれます。

## アプリとしてインストール（PWA、v1.1）

https で公開したページ（GitHub Pages など）を開くと、アプリとしてインストールできます。ファイル（file://）で開いた場合は、これまでどおりブラウザ上で動作します。

### 公開（GitHub Pages）

1. GitHub のリポジトリ → Settings → Pages を開きます。
2. Source を「Deploy from a branch」にし、Branch を `main`・`/ (root)` にして Save します。
3. 数分後、`https://<ユーザー名>.github.io/webclip/` で開けるようになります（`index.html` から `WebClip.html` へ転送します）。

### インストール

| 端末 | 手順 |
|---|---|
| Android（Chrome） | 公開ページを開き、メニュー（︙）→「アプリをインストール」（または「ホーム画面に追加」→「インストール」） |
| iPad（Safari） | 公開ページを開き、共有ボタン →「ホーム画面に追加」 |
| PC（Chrome・Edge） | アドレスバー右端のインストールボタン |

- Android の Chrome がインストール用の APK（WebAPK）を作って入れるので、アプリ一覧に普通のアプリとして並びます。
- インストールしたアプリと、Chrome で開いた同じ URL のページは、保存データが共通です。
- オフラインでも起動します。オンラインのときは、起動するたびに最新版を読み込みます。
- 一度でもインストールした後で公開ファイルを更新すれば、アプリにも反映されます（入れ直す必要はありません）。

### 共有メニューから保存（Android）

- インストールすると、Chrome などの「共有」メニューに WebClip が出ます。
- ページを共有すると、URL とタイトルを受け取り、「リンクのみ」の確認画面が開きます。
- 文字を選択して共有すると、その文字を本文として、URL と一緒に受け取ります（URL の `#:~:text=` は除きます）。
- 共有で受け取れるのは URL・タイトル・文字だけです。記事を丸ごと保存するときは、ブックマークレットを使ってください。

## ブックマークレットの登録

ブックマークレットは2種類あります（v1.2.1）。

| | 短い版（おすすめ） | 完全版 |
|---|---|---|
| 長さ | 約 650 文字 | 約 19,000 文字 |
| 仕組み | 実行時に、公開ページの `bm.js`（本体）を読み込む | 本体をすべて含む |
| アプリ更新時 | 自動で最新版になる（登録し直し不要） | 登録し直しが必要 |
| 必要なもの | https での公開（GitHub Pages など）・インターネット接続 | なし（ファイルで開いたアプリからも作れる） |
| 動かないページ | 外部スクリプトの読み込みを禁止しているページ（「読み込めません」と表示） | インラインスクリプトを禁止しているページ（何も起きない） |

- スマホのブックマーク編集欄は長い URL が途中で切れることがあるので、スマホでは短い版を使ってください。完全版を登録した場合は、URL の最後が `void%200`（または `void 0`）で終わっているか確認してください。
- `bm.js` は `WebClip.html` から `node tools/build-bm.js` で生成します。`WebClip.html` のブックマークレット部分を変えたら、必ず生成し直してください（テストで一致を確認します）。

| 端末 | 登録 | 実行 |
|---|---|---|
| PC（Chrome・Edge） | 「WebClip」ボタンをブックマークバーへドラッグ | ブックマークバーの WebClip をクリック |
| iPad（Safari） | 適当なページをブックマーク → 編集でアドレスを「コードをコピー」した内容に置き換え | ブックマーク一覧から WebClip を選ぶ |
| Android（Chrome） | 適当なページをブックマーク → 編集で URL をコードに置き換え | アドレスバーに「WebClip」と入力し、候補のブックマークをタップ（ブックマーク一覧から開いても動かない） |

- ブックマークレットには、登録したときのアプリの URL が埋め込まれます（「アプリへ送る」の送り先）。アプリの置き場所を変えたら登録し直してください。
- アプリを更新してブックマークレットの機能が変わったときも、登録し直してください。v1.1 以前のブックマークレットで取り込むと、アプリが「古い版です」と案内します（画像の保存は v1.2 から）。
- 外部ファイルを読み込まず、`<style>` 要素も挿入しない作りなので、CSP（Content Security Policy）でスタイルを制限しているページでもパネルが表示されます（テストで確認済み）。ブラウザやサイトによってはブックマークレットの実行自体が制限される可能性はあります（実機では未確認）。その場合は「貼り付け」で取り込んでください。

## 制限事項

- 取得できなかった画像は、元サイトの URL を参照します。元サイトで画像が削除されたり、直リンクが禁止されたりすると表示されません。表示するときは Referer を送りません。
- 保存済みの記事の画像を後から保存する場合（閲覧画面の「画像を端末に保存」、確認画面の「残りの画像を取得」）は、アプリから取得します。このときは、他サイトからの読み込みを許可している画像しか取得できません。記事と同じサイトの画像を取るには、ブックマークレットで取り込み直してください。
- 並べ替えでは更新日時を変えません。そのため、別の端末のバックアップを読み込んで統合するとき、並び順だけの変更は反映されないことがあります。
- 本文の自動抽出は、段落の文字量・読点の数・リンクの割合などから推定しています。サイトによっては本文の一部が欠けたり、余分な部分が入ったりします。その場合は「全体」か「選択」を使ってください。
- 動画・音声・SVG・フォームは取り込みません。iframe（動画の埋め込みなど）はリンクに置き換えます。
- 「続きを読む」などで隠れている部分（非表示の要素）は取り込みません。展開してから実行してください。

## 検証

Playwright（Chromium）による実ブラウザテストです。

```
node tests/e2e.test.js
```

テストではアプリとテスト用記事ページ（`tests/fixtures/`、CSP あり）をローカルで配信し、次の流れを確認します。

- ブックマークレットの実行 → コピー → 貼り付け → 保存
- アプリへ送る
- 普通の貼り付けと XSS 対策
- リンクのみの保存
- 重複 URL の判定
- 検索・絞り込み
- Markdown／HTML の書き出し
- JSON バックアップの書き出し・読み込み
- スマホ幅の表示
- PWA：マニフェスト・アイコン、Chromium の判定でインストール可能か、オフライン起動、共有メニューからの起動
- 画像の保存：同一オリジン・CORS 許可・CORS 不許可・300KB 超の画像（縮小と JPEG 化）、アプリ側での後からの取得
- タグ：チップ表示・過去のタグの候補・絞り込み・タグ管理（名前変更・統合・削除）
- 手動並べ替え：ドラッグ・仕切りの追加・編集、再読み込み後も保持、バックアップに含まれること
